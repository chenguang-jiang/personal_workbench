## DeepSeek 自动归档

- 使用本机已配置的 DeepSeek 官方 API 密钥，密钥只保存在服务器环境文件中，不进入浏览器和代码仓库。默认模型 `deepseek-flash`。
- 支持粘贴文本、选择或拖入 `.md` / `.txt`；单文档最多 1MB，每批最多 10 个，依次处理。
- AI 只返回标题、标签、已有目录和归档理由，不执行文档内指令，不执行系统命令，也不改写正文。目录必须在服务器提供的列表中，路径不允许穿越或使用符号链接。
- 信心不足、目录无效或 AI 暂不可用时保存到 `JCG/00-Inbox`，界面明确显示待整理或服务提示。
- 只有同标题候选、同目录且高置信度识别为同一篇文档时才覆盖更新。写入前将旧文件保存到 `versions`；其他同名内容增加文件名后缀，避免覆盖。
- 相同上传内容通过哈希凭据去重；新文件采用临时文件后原子替换。内容保存后同步 Article、知识节点与关系，并只重建该文档的检索分片。
- 云端导入模式不运行文件监听器，首次启动校准一次索引；每次导入显式更新索引，避免重复监听与导入竞争。
- 若文件已保存但索引失败，接口返回明确的待索引状态，网页保留原路径并提供「重试索引」。

## 构建与启动

部署前先执行 `git fetch origin main`，核对 `origin/main` 的最新提交与当前构建源码。不能只看本机 `HEAD` 或沿用旧构建目录；本机工作区还包含云端功能，应合并上游改动并保留这些功能后再构建。2026-10-29 已合入上游 `d502dd8` 的阅读目录、日期、阅读时长和字体字号设置，样式适配到拆分后的 `src/styles/`，Markdown 标题锚点适配到共享渲染器。

本次构建来源和关键源码摘要保存在服务器 `/srv/dawnkb/runtime/reader-release.json`，对应镜像通过 `cn.chenguangjiang.dawnkb.upstream-revision` 标签记录上游提交。增量构建时传入 `--build-arg DAWNKB_UPSTREAM_REVISION=<上游完整提交>`；上线后核对镜像标签及 `.next/BUILD_ID`，并在正式阅读页检查目录跳转、日期、阅读时长、字体与字号切换，不能仅以容器健康检查作为完成依据。

推荐在资源充足的构建机器使用根目录 `Dockerfile` 构建 Linux amd64 镜像，再导入服务器。

也可使用本机 `next build --webpack` 生成 `.next`，在服务器通过 Node 24 安装 Linux 生产依赖。将 `.next`、生产 `node_modules`、`public`、Prisma 文件与项目配置放入 `/srv/dawnkb/runtime`，使用 `deploy/cloud/Dockerfile.runtime` 制作运行镜像。Prisma 客户端必须在 Linux 中生成，不能直接复制 macOS 的依赖。

服务器启动：

```sh
sh /srv/dawnkb/deploy/start.sh
docker compose -f /srv/dawnkb/deploy/compose.yaml ps
docker logs --tail 100 dawnkb-web
```

`start.sh` 会检查数据库的私有网络、执行版本迁移，再启动服务。若通过 1Panel 升级并重建 PostgreSQL 容器，需要重新运行它；数据库容器名称改变时也要更新脚本。

项目历史迁移缺少部分建表步骤，当前云端在确认没有业务数据后，使用 `bootstrap-new-database.sh` 按当前 schema 建立完整数据结构和迁移基线，并验证数据库与 schema 没有差异。以后日常启动仍使用 `start.sh`。初始化脚本会拒绝含任何业务数据的数据库，不得移除此保护来强行运行。

服务器构建完成后已清理 `/srv/dawnkb/runtime/node_modules`，释放临时安装占用的空间；运行依赖保存在镜像中，重建镜像前需要重新安装 Linux 依赖。

## 备份与恢复

服务器 `/etc/cron.d/dawnkb-backup` 每天 02:15 执行 `backup.sh`，保留约 7 天。每份包含 PostgreSQL 自定义格式备份、知识库文件压缩包、服务环境配置；只有带 `COMPLETE` 的目录才视为成功。

当前快照存于同一服务器磁盘，不能抵御整机或整盘丢失。本地仍保留源文档；数据库与配置的独立异地备份需要另行接入。

恢复应先停止应用，选定已完成的备份，恢复文件与环境配置，再由 PostgreSQL 管理账号将 `database.dump` 恢复至 `dawnkb` 数据库。恢复前先备份当前状态；不要对其他数据库执行恢复。恢复后运行 `start.sh` 并检查文档同步日志。

## 云端编辑、链接与 Markdown 索引

- 阅读页的「编辑」按钮可以直接修改云端正文，点「完成」保存。并发版本不一致时拒绝覆盖并提示刷新；每次保存保留旧版。
- 「AI 导入」支持上传、粘贴和链接三种入口。链接抓取公开 HTML、Markdown 或纯文本，保留来源地址；登录页面和动态页面建议粘贴正文。单篇正文上限 1MB。
- 链接只允许公开 HTTP(S) 地址，限制端口、响应大小和跳转次数；每一跳检查 DNS 并固定已验证的目标地址。
- DeepSeek 可选择相关的现有 Markdown 索引，系统同时维护最近的通用目录页。没有可用索引时创建当前目录的「索引.md」。在原索引末尾维护带标记的 wikilink 条目，不重写手工内容，不重复追加，索引旧版同样备份。
- 「每日热点」菜单与内容抓取已移除，旧页面跳转阅读器，旧 API 返回 410。
