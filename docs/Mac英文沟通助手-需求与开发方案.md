# Mac 英文沟通助手：需求与开发方案

更新日期：2026-10-25

状态：已实现 Mac 首版应用，代码与使用说明见 [DawnTranslate](../mac-apps/DawnTranslate/README.md)。应用编译、本机 OCR、系统英文音频生成与 DeepSeek 真实示例请求已验证；Teams 实机通话尚未验收。

## 一、已经确认的需求

- 使用平台：Mac 桌面软件。
- 邮件：输入截图或英文原文作为上下文，再输入自己的回复意图，生成英文回复。
- 翻译：英文文本翻译成中文。
- 会议：主要使用 Microsoft Teams，将对方的英文实时翻译成中文。
- 回答：自己说中文，软件生成英文语音，并传进 Teams，让参会者听到。

## 二、首版使用流程

### 邮件助手

1. 粘贴截图、导入图片，或粘贴英文邮件；支持追加多张截图。
2. 识别截图文字，允许用户修正识别错误。
3. 显示英文原文与中文翻译。
4. 用户输入中文回复意图，选择简洁、正式或友好的语气。
5. 结合邮件上下文生成英文邮件，同时提供中文释义供核对。
6. 复制英文回复，由用户在邮件软件中发送。

生成回复不得自行添加未提供的日期、价格、交付承诺或其他事实；上下文不足时提示补充。

### 文字翻译

1. 输入英文，生成中文译文。
2. 原文和译文并排显示，支持复制、重新翻译与清空。
3. 翻译失败后保留输入，显示可重试的错误。

### Teams 会议字幕

1. 首次使用引导授权音频捕获，并选择 Teams 作为音源。
2. 开始监听后，以浮动字幕窗显示英文识别结果和中文翻译。
3. 临时识别结果与确定文本区分显示，避免把持续变化的临时结果重复追加。
4. 支持暂停、恢复和结束；音源中断或权限缺失时明确提示。
5. 默认显示中文字幕，不自动朗读中文；这是待体验验证的设计默认值。

“实时”按逐句增量输出设计，实际延迟取决于断句、网络和所用服务，首版通过实测报告延迟，不承诺零延迟。

### 中文语音回答

1. 按住说话按钮或快捷键，向软件使用的真实麦克风说中文。
2. 松开后完成识别，翻译成适合口头表达的英文。
3. 默认展示英文并点击“发送语音”后送入 Teams；另提供可选的“松开后自动发送”。该确认步骤是产品默认值，尚非用户明确指定。
4. 英文语音播放期间提供“立即停止”；排队发送保持原顺序，不叠加播放。
5. 保留中文识别与英文文本，便于修正或复制到会议聊天。
6. 设备未连接时阻止发送并保留内容，不显示虚假的“发送成功”。

## 三、Teams 音频连接

建议验证的独立通道如下：

```text
Teams 接收到的英文声音 → 应用音频捕获 → 英文识别 → 中文翻译 → 浮动字幕窗

真实麦克风 → 中文识别 → 英文翻译 → 英文语音合成
                                            ↓
                                      虚拟音频设备
                                            ↓
                                      Teams 麦克风
                                            ↓
                                         参会者
```

- Teams 的扬声器选择正常耳机；Teams 的麦克风选择虚拟音频设备。
- 本软件的输入选择真实麦克风；英文语音输出单独指定到虚拟音频设备。
- Teams 的接收声音不送入虚拟麦克风，系统提示音也不进入发送通道。
- 不把整个系统默认输出统一切换到虚拟麦克风，以免会议声音被回送。
- 普通发言模式可在软件内切换为真实麦克风透传；默认翻译模式不转发中文原声。
- 使用耳机作为首版推荐配置，并验证插拔、蓝牙切换、采样率变化和重新连接。

可用 BlackHole 2ch 验证虚拟麦克风方案。它属于额外安装依赖；本次未安装驱动、未修改系统声音设置，也未操作 Teams。

可优先评估 ScreenCaptureKit 的应用音频捕获能力，并排除本软件自身声音；能否在目标 macOS 和 Teams 版本上稳定捕获，必须通过实际测试确认。

## 四、实现方向与服务边界

建议独立建立 Mac 原生应用，优先评估 SwiftUI、Vision OCR、ScreenCaptureKit 与 Core Audio；不接入当前知识工作台的页面、数据库或 Obsidian 知识库。

首版先分离五种能力：图片文字识别、语音识别、文字翻译、邮件生成、英文语音合成。翻译与邮件生成可共用文字模型；会议语音识别需支持持续输入和增量结果。

尚未选定模型服务商。文字服务、语音识别和语音合成需要分别验证能力，不假设一个兼容接口就支持全部功能，也不在选定前承诺费用或延迟。未连接服务时显示配置说明，不以演示结果冒充真实翻译。

密钥放入 macOS 钥匙串。截图识别优先在本机进行；如果翻译或语音使用云端服务，配置时说明哪些文本或音频会发给该服务。默认不落盘保存会议原始音频；历史记录提供主动保存与删除。

## 五、开发顺序

1. **先验证 Teams 双向音频。** 输入一段中文，生成英文语音并经虚拟麦克风传给测试参会者；同时捕获对方语音，确认不发生回送。这是最先需要消除的实现风险。
2. **完成文字翻译与邮件闭环。** 接通截图识别、上下文回复、中文释义和复制。
3. **完成会议字幕。** 接通流式识别、逐句翻译、字幕浮窗与暂停恢复。
4. **完成中文语音发言。** 接通真实麦克风、快捷键、发送预览、中断和设备切换。
5. **打包与实机验收。** 检查首次授权、重启、权限撤回、服务失败与 Teams 通话，随后再评估签名及分发。

以上顺序为建议，未给出工期或费用承诺。

## 六、首版验收标准

| 场景 | 通过条件 |
| --- | --- |
| 邮件截图 | 能识别英文、修改识别文字，并根据中文意图生成符合上下文的回复 |
| 文字翻译 | 原文和译文可对照、复制；失败不丢输入 |
| 对方连续讲话 | 中文字幕逐句更新，确定内容不重复、不乱序；记录实际延迟 |
| 中文语音回答 | 测试参会者实际听到英文语音，翻译模式下不收到中文原声 |
| 音频隔离 | 对方声音与本软件合成声音不被反复发送或翻译 |
| 停止发送 | 点击停止后中断后续输出；已经传出的声音无法撤回 |
| 权限或网络异常 | 明确说明原因，保留待发送文字，不误报发送成功 |
| 设备变化 | 耳机或虚拟设备断开时提示并安全暂停，不自行改用扬声器发送 |

## 七、核对依据

- [Microsoft：Teams 设备设置](https://support.microsoft.com/en-us/teams/notifications-settings/manage-your-device-settings-in-microsoft-teams)：Teams 支持分别选择扬声器和麦克风。
- [Microsoft：会议音频设置](https://support.microsoft.com/en-us/teams/meetings/manage-audio-settings-in-microsoft-teams-meetings)：部分设置可能受会议组织者或 IT 管理策略影响。
- [BlackHole：作为虚拟麦克风使用](https://github.com/ExistentialAudio/BlackHole/wiki/Use-BlackHole-as-a-Virtual-Microphone)：说明应用音频如何送入其他应用的音频输入。
- [Apple：ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos) 与 [排除当前进程音频](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/excludescurrentprocessaudio)：用于后续音频捕获方案评估。

上述资料支持技术方案评估，不等同于本应用已经实现或验证。
